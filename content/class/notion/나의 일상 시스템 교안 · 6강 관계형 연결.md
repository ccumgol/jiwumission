## 이 강의 핵심 메시지

> 그리고 1강에서 한 약속을 지키는 시간이기도 합니다."

> ⭐ **1강의 약속을 반드시 먼저 꺼내세요.**

🗣 "1강에서 제가 뭐라고 했죠? '`결제수단`은 지금 선택 속성인데, 나중에 관계형으로 바꿀 거니까 **이름을 바꾸지 마세요**'라고 했습니다.

**오늘 그걸 합니다.**"

학습자가 "아 그거!" 하는 순간, 강좌 전체가 하나로 꿰어집니다.

## 1. 왜 필요한가 (8분 — 개념에 시간을 쓰세요)

### 선택 속성의 한계 (`10-001`)

칠판이나 화면에 이 표를 그려주세요.

| 알고 싶은 것 | 선택 속성으로 | 관계형으로 |
| --- | --- | --- |
| "신한카드로 결제되는 구독" | ✅ 필터로 가능 | ✅ |
| "신한카드 **결제일이 며칠**이지?" | ❌ **못 적는다** | ✅ 카드 페이지에 적는다 |
| "신한카드로 이번 달 **얼마** 나갔지?" | ❌ **못 구한다** | ✅ 자동 합계 (7강) |
| "이 구독의 **실제 결제 내역**" | ❌ | ✅ |

> ⭐ **핵심 비유 — 글자 vs 물건**

🗣 "선택 속성의 '신한카드'는 **글자 세 개**입니다. 관계형의 '신한카드'는 **페이지 하나**예요.

글자에는 아무것도 못 적습니다. 페이지에는 결제일도, 한도도, 메모도 적을 수 있고 **그 카드로 결제된 것들이 자동으로 모입니다.**

**더 적을 게 생기면 관계형으로 바꿀 때입니다.**"

### 언제 관계형으로 바꾸나 — 판단 기준

> 🗣 "선택 속성으로 둘지 관계형으로 바꿀지, 기준은 이겁니다."

```
그 값 자체에 대해 더 적을 게 있나?

  없다  →  선택 속성으로 충분    (예: 주기 = 월/연)
  있다  →  관계형으로            (예: 결제수단 → 결제일, 한도, 메모)
```

## 2. 따라 만들기

### 단계 1 — 💳 결제수단 DB 만들기

```
🗄 데이터 창고 → /표 → 「표 보기」 → 새 데이터베이스
이름:  💳 결제수단
```

| 속성 | 유형 | 비고 |
| --- | --- | --- |
| 수단명 | 제목 | `신한카드` `국민카드` … |
| 종류 | 선택 | `신용카드` `체크카드` `계좌` `현금` `간편결제` |
| 결제일 | 숫자 | ★ **선택 속성으로는 못 적던 것** |
| 메모 | 텍스트 | 혜택, 한도 등 |
| 사용중 | 체크박스 | 안 쓰는 카드 거르기 |

내용을 채웁니다 — **1강 구독 DB의 ****`결제수단`**** 선택지와 같은 이름으로.**

| 수단명 | 종류 | 결제일 |
| --- | --- | --- |
| 신한카드 | 신용카드 | 25 |
| 국민카드 | 신용카드 | 14 |
| 계좌이체 | 계좌 |  |
| 현금 | 현금 |  |

> 💡 **여기서 ****`결제일`****을 적는 순간을 짚어주세요.**

🗣 "보세요. 지금 '신한카드는 25일에 빠진다'고 적었죠. **선택 속성이었으면 이걸 적을 데가 없었습니다.** 이게 관계형으로 바꾸는 이유입니다."

### 단계 2 — 구독 DB에 관계형 추가 (`10-002`)

```
🧾 구독 서비스 DB 로 갑니다
  → 오른쪽 끝  +
  → 이름:  결제수단(관계형)
  → 유형:  「관계형」
  → 연결할 DB:  💳 결제수단
  → 「양방향」 켜기  ← ⚠️ 중요
```

> ⭐ **양방향을 반드시 켜세요** (`10-003`)

🗣 "**양방향(2-way)**을 켜면 구독에서 카드를 고르는 순간, **카드 쪽에도 그 구독이 자동으로 나타납니다.**

한 번만 적으면 양쪽에서 다 보이는 거죠.

단방향으로 하면 카드 페이지를 열어도 어떤 구독이 붙었는지 안 보입니다. 이 강좌에서는 **항상 양방향**으로 하세요."

화면에서 「양방향」「2-way」「Show on 💳 결제수단」 등으로 표기가 다를 수 있습니다.

### 단계 3 — 기존 구독을 카드에 연결 (10분)

구독 DB의 새 열에서, 각 구독마다 카드를 고릅니다.

```
「결제수단(관계형)」 칸 클릭 → 카드 이름 검색 → 선택
```

> ⚠️ **기존 ****`결제수단`**** 선택 속성을 보면서 옮기면 빠릅니다.**
"선택 속성에 적힌 걸 보고 관계형에 똑같이 고르시면 됩니다."

### 단계 4 — ★ 양방향 확인 (감동 포인트)

> ⭐ **이걸 꼭 같이 해보세요. 오늘의 하이라이트입니다.**

🗣 "보세요. **아무것도 안 했는데 구독 목록이 여기 들어와 있습니다.**

구독 쪽에서 카드를 고른 것뿐인데, 카드 쪽에서도 보이죠. 이게 양방향입니다."

```
💳 결제수단 DB 를 엽니다
  → 「신한카드」 행을 클릭해서 페이지를 엽니다
```

### 단계 5 — 가계부에도 관계형 2개

```
💰 가계부 DB 로 갑니다

① + → 이름: 결제수단(관계형)
     유형: 관계형 → 💳 결제수단 → 양방향

② + → 이름: 연결된 구독
     유형: 관계형 → 🧾 구독 서비스 → 양방향
```

②가 **5강에서 예고한 것**입니다.

```
가계부의 「Netflix Premium $26.99」 행
  → 「연결된 구독」 칸 클릭
  → 구독 DB의 「Netflix Premium」 선택
```

> 🗣 "이제 노션이 **이 둘이 같은 넷플릭스인 걸 압니다.**

> 

> 구독 DB에서 넷플릭스 페이지를 열어보세요.

> **실제 결제 내역이 쌓여 있죠.** 매달 결제될 때마다 여기 늘어납니다."

### 단계 6 — 삼각형 구조 확인

```
🧾 구독 ──────▶ 💳 결제수단
   ▲                 ▲
   │                 │
   └──── 💰 가계부 ───┘
```

> 🗣 "세 DB가 삼각형으로 연결됐습니다.

> 어디서 시작하든 나머지 둘로 갈 수 있어요."

## 3. ★ 선택 속성을 지울까 (5분)

> 🚨 **여기서 반드시 브레이크를 거세요.**

🗣 "이제 `결제수단` 선택 속성은 필요 없어 보이죠. **지우지 마세요. 아직은요.**

속성을 지우면 그 안의 값은 **되돌릴 수 없습니다.** (`07-020`) 관계형을 다 연결했는지 확인하고, **2주쯤 써보고** 지우세요.

저는 아예 안 지우고 백업으로 두는 걸 권합니다."

지울 때의 안전 순서:

```
1. 관계형이 빈 행이 없는지 확인 (필터: 관계형이 비어 있음)
2. 2주간 써본다
3. 그래도 필요 없으면 지운다
```

## 4. 흔한 실수

| 실수 | 증상 | 해결 |
| --- | --- | --- |
| **양방향을 안 켬** | 카드 쪽에서 구독이 안 보인다 | 속성 설정에서 켠다 (`10-003`) |
| 카드 이름을 다르게 적음 | 연결할 때 못 찾는다 | 이름 통일 |
| 관계형 대신 **텍스트**로 입력 | 연결이 안 된다 | 유형을 관계형으로 |
| 관계형을 만들자마자 선택 속성 삭제 | 값이 날아간다 | **나중에** (`07-020`) |
| 카드마다 DB를 따로 만듦 | DB가 10개가 된다 | 카드는 **한 DB의 행** |
| 연결을 일부만 함 | 7강 합계가 틀린다 | 전부 연결 확인 |

> ⚠️ **"카드마다 DB를 따로 만들었어요"가 개념 오해의 대표 신호입니다.**

🗣 "신한카드 DB, 국민카드 DB를 따로 만드신 분? **카드는 DB가 아니라 행(항목) 하나입니다.**

구분 기준: **같은 속성을 갖는 것끼리는 한 DB**입니다. 신한카드도 국민카드도 '이름·종류·결제일'을 갖죠? 그럼 한 DB예요." (`11-007`)
