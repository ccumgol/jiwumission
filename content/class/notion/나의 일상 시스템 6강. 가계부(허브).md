## 이 강의 핵심 메시지

> 🗣 "지금까지는 DB가 **하나**였습니다. 오늘부터 **둘**이 됩니다.

> 그리고 이 둘을 어떻게 나누느냐가 이 Part의 주제입니다."

---

## 1. 왜 필요한가 (7분 — 개념이 핵심입니다)

### 구독 DB로는 답할 수 없는 질문

> 🗣 "지금 구독 DB에 물어볼 수 없는 걸 하나 말씀드릴게요.
> **'이번 달에 실제로 돈이 얼마 나갔지?'
> **구독 DB는 '매달 $26.99 나갈 예정'이라고만 알려줍니다.
> **실제로 나갔는지는 모릅니다.** 중간에 해지했을 수도 있고요."

### 목록과 기록은 다릅니다

> ⭐ **이 구분이 5강의 전부입니다.**

🗣 "**한 줄이 뭘 뜻하는지**가 다르면 DB를 나눠야 합니다. 이게 DB를 나눌지 합칠지 판단하는 기준입니다." (`07-004` `11-007`)

|  | 🧾 구독 DB | 💰 가계부 DB |
| --- | --- | --- |
| 무엇 | **목록** | **기록** |
| 한 줄의 뜻 | "넷플릭스를 구독 중이다" | "9월 5일에 $26.99 나갔다" |
| 넷플릭스가 | **한 줄** | 매달 한 줄씩 **12줄** |
| 바뀌는 때 | 구독을 시작/해지할 때 | 결제될 때마다 |

### 허브 DB란 (`11-008`)

> 🗣 "가계부는 **허브**가 될 겁니다.
> 허브는 **여러 곳의 데이터가 모이는 중심**이에요."

```
구독 결제  ─┐
카드 사용  ─┼─▶  💰 가계부
현금 지출  ─┘
```

> 🗣 "돈이 나가는 건 전부 여기로 들어옵니다.
> 그래서 '이번 달 얼마 썼지?'에 답할 수 있게 되죠."

## 2. 따라 만들기

### 단계 1 — DB 만들기

```
🗄 데이터 창고 → /표 → 「표 보기」(데이터베이스) → 새 데이터베이스
이름:  💰 가계부
```

> 💰 **금액 속성은 반드시 달러($) 형식으로.**
구독 DB도 달러입니다. 통화가 섞이면 **7강에서 만들 합계가 뜻 없는 숫자**가 됩니다.

### 단계 2 — 속성 7개

| # | 속성 | 유형 | 설정 | 매뉴얼 |
| --- | --- | --- | --- | --- |
| 1 | 내용 | 제목 | 뭘 샀는지 |  |
| 2 | 금액 | 숫자 | **달러($)** | `08-006` |
| 3 | 날짜 | 날짜 |  | `08-010` |
| 4 | 분류 | 선택 | 아래 9개 | `08-007` |
| 5 | 결제수단 | 선택 | ★ 6강에서 관계형으로 | `08-007` |
| 6 | 고정/변동 | 선택 | `고정` `변동` | `08-007` |
| 7 | 메모 | 텍스트 |  |  |

### 단계 3 — 분류를 9개로 제한한다 (`11-010`)

```
식비 · 교통 · 주거 · 통신 · 구독 · 의료 · 문화 · 쇼핑 · 기타
```

> ⭐ **왜 9개로 제한하나 — 이 설명을 꼭 하세요**

🗣 "분류를 세밀하게 나누고 싶어집니다. '식비'를 '외식/장보기/카페/배달'로 나누고 싶죠.

그런데 분류가 20개가 되면 **입력할 때마다 고민**하게 됩니다. '이건 외식인가 카페인가?' 하고 3초 멈추면, 그 3초 때문에 **다음부터 입력을 안 합니다.**

**9개 이하.** 나중에 정말 필요하면 그때 늘리세요." (`11-010`)

### 단계 4 — `고정/변동`의 쓸모 설명

> 🗣 "이 속성이 왜 있을까요?
> **돈을 줄이려면 고정비부터 봐야** 하기 때문입니다.
> 커피 한 잔 아끼는 건 $5인데, 안 쓰는 구독 하나 끊으면 매달 $10입니다.
> **한 번의 결정으로 매달 절약되는 게 고정비**예요."

| 고정 | 변동 |
| --- | --- |
| 구독료, 통신비, 월세, 보험 | 식비, 쇼핑, 교통, 문화 |
| 한 번 정하면 계속 나감 | 그때그때 다름 |
| **줄이려면 여기부터** | 의지력이 필요함 |

### 단계 5 — 실제 지출 입력 (10분)

```
이번 주 지출을 5~10건 넣어봅니다.
  · 카드 앱이나 은행 앱을 보며
  · 금액은 USD로
  · 구독 결제는 분류를 「구독」으로  ← 6강에서 연결할 것들
```

> 💡 **"이번 달 전부"는 너무 많습니다.**
"이번 주만" 또는 "기억나는 것만" 으로 시작하게 하세요.
전부 넣으려다 지쳐서 포기하는 경우가 많습니다.

### 단계 6 — 보기 만들기

| 보기 이름 | 설정 |
| --- | --- |
| `5강 · 💰 이번 달 지출` | 정렬: 날짜 내림차순 |
| `5강 · 📊 분류별` | 그룹: 분류 (`09-026`) |

**그룹 보기를 꼭 만들어 보여주세요.** (`09-026`)

```
보기 만들기 → 「그룹」 → 분류 선택
→ 각 그룹 아래 「계산」 → 합계
```

> 🗣 "분류별로 묶이고, **그룹마다 합계**가 나옵니다.
> '아 이번 달 식비가 이만큼이었구나'가 여기서 처음 보이죠." (`09-028`)

### 단계 7 — 홈에 올릴지 결정

> ⚠️ **홈은 이미 2~3개가 올라가 있습니다.**
가계부까지 올리면 몇 개가 되는지 세어보게 하세요.
5개를 넘으면 **덜 보는 걸 토글로 접거나 내립니다.** (`11-017`)

## 3. ★ 6강 예고를 반드시 한다 (2분)

> ⭐ **이 예고가 6강의 동기를 만듭니다.**

🗣 "지금 가계부에 '넷플릭스 $26.99'를 적었죠. 그런데 구독 DB에도 넷플릭스가 있습니다.

**같은 넷플릭스인데 두 군데 따로 적혀 있습니다.**

지금은 노션이 이 둘이 같은 건지 모릅니다. 다음 시간에 **연결**합니다. 연결하면 —

· 구독 페이지를 열면 **실제 결제 내역이 다 보이고**
· '이 카드로 이번 달 얼마 나갔지?'를 **자동 계산**하게 됩니다"

그리고 1강의 약속을 다시 상기시킵니다.

> 🗣 "1강에서 `결제수단`을 선택 속성으로 만들면서 **이름을 바꾸지 말라**고 했죠.
> 다음 시간에 그걸 씁니다."

## 4. 흔한 실수

| 실수 | 증상 | 해결 |
| --- | --- | --- |
| 구독 DB에 지출을 기록함 | 한 줄의 뜻이 섞인다 | 목록과 기록을 분리 (`07-004`) |
| 분류를 20개 만듦 | 입력할 때마다 고민, 결국 안 씀 | 9개로 (`11-010`) |
| 금액을 원화로 입력 | 구독 DB와 통화가 섞인다 | **USD로 통일** |
| `고정/변동`을 비워둠 | 고정비 합계를 못 낸다 | 입력할 때 같이 |
| 이번 달 전부 입력하려다 지침 | 5강에서 진이 빠진다 | 이번 주만 |
| DB를 홈에 만듦 | 0강 규칙 위반 | 창고로 (`03-007`) |
